Hexo post_asset_folder 图片显示问题修复

发表于 2026-07-26 分类于 经验总结 阅读次数： Valine： 1.3k 5 分钟

背景

我的博客文章组织和大多数 Hexo 用户不太一样——我习惯用 Obsidian 写文章，并且让图片和 markdown 文件保持在同一级目录。

原有的目录结构大致是：

在 Hexo 默认开启 post_asset_folder: true 的情况下，图片却一直无法正常显示——<img> 的 src 指向了根目录 /output_6_1.png，自然 404。

本文记录排查和修复的全过程。

问题分析

post_asset_folder 的原理

当 _config.yml 中启用了：

Hexo 会为每篇文章创建一个同名子文件夹作为资源目录。例如：

  • 文章：source/_posts/my-post.md
  • 资源文件夹：source/_posts/my-post/（与 md 同级，是一个文件夹）

在 hexo-renderer-marked 插件中，postAsset: true 会让 markdown 图片语法 ![](image.png) 解析到该资源文件夹。

我遇到的冲突

我的文章在文件夹中，且文件夹名和文章名相同：

这种情况下，Hexo 计算的 asset_dir 是：

注意，这里出现了 两层 Regression/——第一层是文章所在的目录，第二层是 Hexo 自动追加的同名子文件夹。

但我的图片放在第一层（和 Regression.md 同级），不在第二层子文件夹里。

所以在构建流程中：

  1. Processing 阶段：scanAssetDir 扫描 .../Regression/Regression/ → 目录不存在 → 没注册任何 PostAsset
  2. processAsset：file.source.startsWith(post.asset_dir) → asset_dir 是 .../Regression/Regression/，而图片在 .../Regression/ → 匹配失败
  3. hexo-renderer-marked 渲染时：postAsset: true 查找 PostAsset.findById("source/.../Regression/Regression/output_6_1.png") → 没找到 → 回退到 url_for("output_6_1.png") → 输出 <img src="/jing-yan-zong-jie/jing-yan-zong-jie/hexopostassetfix/output_6_1.png" > → 404

关键代码路径

这是 hexo-renderer-marked 中 postPath 的计算方式：

postSource 是文章在数据库中的 source 字段，值为 "_posts/人工智能/Regression/Regression.md"：

  • dirname → "_posts/人工智能/Regression"
  • basename（去掉 .md）→ "Regression"
  • join("source", "_posts/人工智能/Regression", "Regression") → "source/_posts/人工智能/Regression/Regression/"

这就是它去查找图片的路径。

然后 PostAsset 的 _id 由 scanAssetDir 按同样规则计算：

其中 assetDir = post.asset_dir = full_source 去掉扩展名 + / = base_dir/source/_posts/人工智能/Regression/Regression/。

两者对得上——前提是图片真在那个子文件夹里。而我的图片不在那里，所以在哪里都对不上。

解决方案

核心思路是在渲染之前纠正图片 URL，在生成阶段把图片复制到正确位置。我用一个 Hexo 脚本（scripts/fix_asset_dir.js）实现了两个过滤器：

Phase 1：注册 PostAsset（before_generate，优先级 1）

在 render_post（默认优先级 ~10）之前运行。扫描符合”同名目录”模式的文章目录，为同目录下的图片手动注册 PostAsset。

这一步让 Hexo 的资源生成器（asset generator）在处理 PostAsset 时把图片复制到 public 目录，且路径为 post.path + slug——也就是和文章 HTML 在同一层。

Phase 2：修复 HTML 中的 <img> 路径（after_post_render）

文章渲染完成后，将 <img src="/jing-yan-zong-jie/jing-yan-zong-jie/hexopostassetfix/output_6_1.png" > 替换为正确的绝对路径：

这样，<img src="/jing-yan-zong-jie/jing-yan-zong-jie/hexopostassetfix/output_6_1.png" > 就变成了 <img src="/jing-yan-zong-jie/jing-yan-zong-jie/hexopostassetfix/ren-gong-zhi-neng" >，和 Phase 1 生成的图片文件路径一致。

多篇受影响的文章（Regression、Classification、Regularization、STM32 等）均自动修复，无需修改 markdown 源文件。

一些思考

为什么不改文章源文件？

我的 Obsidian 和 Hexo 共享同一套源文件。Obsidian 中图片就是和 md 同级的相对路径，改了 Hexo 的构建逻辑去适配它，比反过来改 Obsidian 配置更可持续。

为什么不用符号链接 / 复制文件到子文件夹？

  • 符号链接在 Windows 上需要管理员权限，且跨平台行为不一致
  • 复制文件会污染 source/ 目录，可能被 git 跟踪或导致构建循环

为什么不直接禁用 post_asset_folder？

禁用后 marked.postAsset: true 不会生效，所有图片路径都需要写绝对路径（如 ![](/人工智能/Regression/output_6_1.png)）。这虽然也能工作，但意味着 Obsidian 和 Hexo 中使用不同的图片引用方式，编辑体验割裂。

完整代码

最终脚本见 scripts/fix_asset_dir.js，约 80 行，支持：

  • 自动识别 category/PostName/PostName.md 模式
  • PNG / JPG / JPEG / GIF / SVG / WebP 等常见图片格式
  • 不影响常规（非同名目录）文章
  • 构建零错误
